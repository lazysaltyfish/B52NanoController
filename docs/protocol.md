# HaisenKeji B52Nano HID 控制协议

> 逆向自原厂 Windows 工具「B52Nano 设置工具 V1.3（适配器助手）」，并在真实硬件
> （固件 v1.0）上逐条验证。本文档按 [SemVer] 精神描述协议：已验证字段标注 ✅，
> 推测字段标注 ⚠️。
>
> 逆向仅出于互操作性目的，本文不含任何原厂代码。

## 1. 设备概览

| 项 | 值 |
|---|---|
| USB VID:PID | `0a12:123b`（0a12 = CSR/Qualcomm） |
| 字符串 | Manufacturer `Qualcomm` · Product `HaisenKeji` · Serial `CBCDAF0123456789` |
| bcdDevice | `26.13`（实测样本） |
| 芯片 | Qualcomm QCC514X（原厂升级包内含 `QCC514X_dfu_file.bin`） |
| 接口 0 | UAC 1.0 AudioControl（Feature Unit：播放音量/静音 + 麦克风电量/静音） |
| 接口 1 | UAC 1.0 AudioStreaming **IN**：16 kHz / mono / S16（HFP 麦克风回传） |
| 接口 2 | UAC 1.0 AudioStreaming **OUT**：48 kHz / stereo / S16，EP `0x03` |
| 接口 3 | **HID 控制通道**：interrupt IN `0x81`，wMaxPacketSize 64，bInterval 1 |

音频路径由系统标准驱动接管（Linux `snd-usb-audio`），无需本项目处理。

## 2. HID 报告描述符

两个 Application Collection：

```text
报告 ID 7 — Consumer（耳机多媒体按键转发，AVRCP → HID）
报告 ID 8 — Vendor Defined (usage page 0xFFA0, usage 0x01)
            Output Report 63 字节（经 SET_REPORT 控制传输下发）
            Input  Report 63 字节（经中断 IN 上报）
```

原始描述符（98 字节，`usbhid-dump` 抓取）：

```
05 0C 09 01 A1 01 85 07 15 00 25 01 09 CD 09 B5
09 B6 09 B7 75 01 95 04 81 02 15 00 25 01 09 B0
09 B1 09 B3 09 B4 75 01 95 04 81 22 15 00 25 01
09 E9 09 EA 09 E2 75 01 95 03 81 22 75 05 95 01
81 01 C0 06 A0 FF 09 01 A1 01 85 08 09 01 15 00
26 FF 00 75 08 95 3F 91 00 09 02 75 08 95 3F 81
00 C0
```

## 3. 帧格式（报告 ID 8）

```text
主机 → 设备:  [0x08] [命令] [参数 …]  剩余补零，共 64 字节（1 报告 ID + 63 payload）
设备 → 主机:  [0x08] [类型] [数据 …]
```

原厂工具对每条命令都是**fire-and-forget**：不等应答即返回，应答经异步回调统一解析。

## 4. 命令表

| 命令 | 帧（不含报告 ID） | 功能 | 实测行为 |
|---|---|---|---|
| Ping | `00 01` | 探活 | ✅ 应答 `FF` |
| 配对 | `01 01` | 进入搜索配对模式 | ✅ 发送即生效，无应答 |
| 连接指定设备 | `02 m0…m5` | 向 6 字节 MAC 发起连接 | ✅ 无应答；MAC 来自「查询最近设备」 |
| 断开 | `03 01` | 断开当前链路 | ✅ 无应答 |
| 查询当前设备 | `04 00` | — | ⚠️ 空闲时无应答；`04` 型报文作为事件推送（见 §5） |
| 查询最近设备 | `0A 01` | 最近连接设备 + 连接状态 | ✅ 应答 `03` 型报文 |
| 查询编码 | `0D 00` | 当前编码 | ⚠️ 连接/播流时应答 `0D` 型报文；空闲时不应答 |
| 锁定设备 | `0F 01` | 仅回连锁定设备 | ✅ 无应答 |
| 解锁设备 | `0F 00` | 解除锁定 | ✅ 无应答 |
| 读版本 | `11 05` | 固件版本 | ✅ 应答 `11` 型报文 |
| 读设置 | `12 00 00 00 00 00` | 设置块 | ✅ 应答 `12` 型报文 |
| 保存设置 | `12 01 [自动配对] [USB隐藏] [输入源=0] [编码位] [Adaptive模式]` | 写设置 | ✅ 无应答；**设备随即自动重启**（数秒） |

## 5. 应答与事件（payload 首字节 = 类型）

### `FF` — Ping 应答
`FF` ✅（其余字节为零）

### `03` — 最近连接设备
```text
03 | MAC[6]        | 连接标志 | 名长 | 名称(UTF-8)
   | b8 20 8e 8d 5e 0a | 01       | 11   | "Technics EAH-AZ80"
```
- MAC：payload[1..6] ✅
- payload[7]：`0`=当前未连接，`1`=已连接 ✅（实测同一设备两种状态分别为 00/01）
- payload[8]：名称长度（字节数）✅；名称自 payload[9] 起 ✅

原厂工具解析到 `03` 后，若处于「回连」流程，则自动以该 MAC 发送 `02` 连接命令。

### `04` — 连接状态事件
```text
04 | … | 名长@payload[7] | 名称自 payload[8] 起
```
- 名长 = 0 → 已断开（原厂 UI 同时清空编码显示）✅
- 由设备在链路建立/断开时主动推送 ⚠️（未在短时抓包中捕获，原厂工具按此处理）

### `0D` — 当前编码
```text
0D | profile@payload[1] | 编码索引@payload[2]
0D | 02                 | 01   → SBC
```
- profile：实测值 `02`（推测 2 = A2DP）⚠️
- 编码索引见 §6 ✅

### `11` — 固件版本
```text
11 | 85(校验)@payload[1] | 主版本@payload[2] | 次版本@payload[3]
11 | 85                  | 01                | 00   → v1.0
```
校验位不为 `0x85` 时原厂工具忽略该报文 ✅

### `12` — 设置块
```text
12 | 自动配对@1 | USB隐藏@2 | 输入源@3 | 编码位@4 | Adaptive模式@5
```
实测样例：

```text
出厂态:    12 | 00 | 00 | 00 | 00 | 00      （编码位=0 → 仅 SBC）
推荐设置后: 12 | 00 | 00 | 00 | 0f | 01
```

### 报告 ID 7 — 耳机多媒体按键（AVRCP 转发）

```text
byte0: bit0 播放/暂停 · bit1 下一曲 · bit2 上一曲 · bit3 停止
byte1: bit0 播放     · bit1 暂停     · bit2 快进     · bit3 快退
byte2: bit0 音量+    · bit1 音量−    · bit2 静音
```

## 6. 编码索引表 ✅

| 索引 | 名称 |
|---|---|
| 0 | （空字符串） |
| 1 | SBC |
| 2 | FastStream |
| 3 | aptX |
| 4 | aptX LL |
| 5 | aptX HD |
| 6 | aptX Adaptive |

> ⚠️ **踩坑记录**：原厂 exe 的 `ldstr` 操作数是未解析的 metadata token
> （形如 `0x70000005`）。低 24 位才是 #US 字符串堆的偏移。若把 #US 堆按顺序
> 当作编码表，会整体**错位一位**（SBC 显示成 FastStream）。务必按偏移取值。

## 7. 设置位定义 ✅

**编码位（`12` 帧 payload[4]）**：bit0 = aptX Adaptive · bit1 = aptX · bit2 = aptX HD · bit3 = aptX LL。
编码在建链时协商；改设置后需断开重连才生效（原厂说明书亦要求）。

**Adaptive 模式（payload[5]）**：`0` = 音质模式 · `1` = 低延时模式。

**自动配对（payload[1]）**：`>0` = 重启 20 s 内回连失败则进入配对模式。

**USB 隐藏（payload[2]）**：`>0` = 未连接耳机时对主机隐藏 USB 声卡（即「自动切换蓝牙音频」）。

## 8. 行为要点（实测）

1. 每条命令固定 64 字节整帧发送（报告 ID + 63 payload，余零填充）。
2. 「保存设置」必然触发设备重启：约 5 s 后恢复响应，设置回读一致。
3. `04`/`0D` 的查询形式在空闲（未连接/未播流）时**静默不应答**，勿当作超时错误；
   信息以事件推送 + 轮询 `0A` 兜底。
4. 向非法前缀（非 `00`/`0A`/…命令集）发送帧：设备静默丢弃；偶发 `EPROTO`（hidraw 写失败），
   重开设备节点即恢复。连续大量非法帧可能令 HID 通道短时无响应，USB 复位/重插可恢复。
5. 原厂工具在设备接入事件后仅发一次 Ping + 各查询；本项目的轮询节奏（5 s）为安全裕量。

## 9. 逆向方法（备忘）

1. `lsusb -v` + `usbhid-dump`（root）取得描述符与报告描述符，定位 `0xFFA0` 厂商通道。
2. `hidraw` 直发探测帧（root + Python `select`），确认帧头与「`0A` → `03` 设备信息」。
3. 原厂 exe 为 .NET WinForms：`dnfile` + `dncil` dump 全部方法的 IL，
   `Device` 类方法即为命令帧构造表（`new byte[64]; [0]=8; [1]=cmd; [2]=param…`）。
4. 关键坑：字符串混淆实为 `ldstr` token 未解析——`token & 0xFFFFFF` = #US 堆偏移。
   按偏移取值后才得到真实编码表与 UI 文案。
5. 全部命令在真机复测：`08 11 05` → `11 85 01 00`（v1.0）、无变化保存 → 回读一致 等。
